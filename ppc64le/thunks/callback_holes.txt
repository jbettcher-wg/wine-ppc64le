# EXPORTS THAT TAKE A GUEST FUNCTION POINTER AND HAVE NO WRAPPING ROW.
#
# Written by callback_audit.py --update-holes and matched EXACTLY by
# check-callback-rows.sh: a new hole fails the gate, and so does a hole that
# gets filled without being struck off here.  Every line below is a decision,
# not an oversight, and the decisions are these three:
#
# 1. A THREAD'S START ROUTINE is already handled one layer down, by
#    thread_start_is_guest_code() at RtlUserThreadStart -- which also gives
#    the thread's guest stack the size the thread asked for.  A row here would
#    route it through a trampoline instead and quietly bypass both.
#    RtlUserThreadStart is in the list for the opposite reason: it takes the
#    entry point because this port CALLS it, and nothing registers there.
kernel32.dll CreateRemoteThread arg3 LPTHREAD_START_ROUTINE
kernel32.dll CreateRemoteThreadEx arg3 LPTHREAD_START_ROUTINE
kernel32.dll CreateThread arg2 LPTHREAD_START_ROUTINE
kernelbase.dll CreateRemoteThread arg3 LPTHREAD_START_ROUTINE
kernelbase.dll CreateRemoteThreadEx arg3 LPTHREAD_START_ROUTINE
kernelbase.dll CreateThread arg2 LPTHREAD_START_ROUTINE
ntdll.dll NtCreateThreadEx arg4 PRTL_THREAD_START_ROUTINE
ntdll.dll RtlCreateUserThread arg6 PRTL_THREAD_START_ROUTINE
ntdll.dll RtlUserThreadStart arg0 PRTL_THREAD_START_ROUTINE
#
# 2. THE CALLBACK TAKES MORE THAN SIX ARGUMENTS.  The trampoline pool has
#    fixed-arity dispatchers for four, five and six and refuses anything else
#    by name (wrap_guest_callback_ex).  Extending it to seven, eight and nine
#    is what these are waiting on: LPPROGRESS_ROUTINE takes nine,
#    PFNCALLBACK and LPCONDITIONPROC eight, PENABLECALLBACK and WINEVENTPROC
#    seven.
advapi32.dll EventRegister arg1 PENABLECALLBACK
kernel32.dll CopyFileExA arg2 LPPROGRESS_ROUTINE
kernel32.dll CopyFileExW arg2 LPPROGRESS_ROUTINE
kernel32.dll MoveFileTransactedA arg2 LPPROGRESS_ROUTINE
kernel32.dll MoveFileTransactedW arg2 LPPROGRESS_ROUTINE
kernel32.dll MoveFileWithProgressA arg2 LPPROGRESS_ROUTINE
kernel32.dll MoveFileWithProgressW arg2 LPPROGRESS_ROUTINE
kernelbase.dll CopyFileExW arg2 LPPROGRESS_ROUTINE
kernelbase.dll EventRegister arg1 PENABLECALLBACK
kernelbase.dll MoveFileWithProgressW arg2 LPPROGRESS_ROUTINE
user32.dll DdeInitializeA arg1 PFNCALLBACK
user32.dll DdeInitializeW arg1 PFNCALLBACK
user32.dll SetWinEventHook arg3 WINEVENTPROC
ws2_32.dll WSAAccept arg3 LPCONDITIONPROC
#
# 3. IsBadCodePtr PROBES a pointer and never calls it.  Wrapping would have it
#    answer about the trampoline instead of about the guest's own code.
kernel32.dll IsBadCodePtr arg0 FARPROC
